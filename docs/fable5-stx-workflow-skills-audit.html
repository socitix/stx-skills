A Relevance Audit

The wave survives Fable 5:
mostly intact, one cracked beam

Your two flagship workflow skills — /stx-feature v1.4.0 and /stx-fix v1.3.0 — were stress-tested against the current Claude Code harness shipped with the Fable 5 model. The architecture holds. One assumption is broken. Six tentative changes are laid out below for your study — nothing has been modified.

Subject  /stx-feature · /stx-fix · 10 personas Scope  Harness compatibility, read-only Status  Audit complete — zero edits applied
THE HEADLINE:  Both skills remain relevant and functional under Fable 5 — they are fully model-agnostic — but the in-subagent user interview in /stx-feature is broken by the current harness, and five modernization opportunities are now on the table.

The Investigation

What we checked, and how

Two parallel deep-reads swept every line of both skill definitions, their catalogs, templates, schemas, and all ten persona files under .claude/agents/. In parallel, a documentation agent verified eight specific harness facts against the current official Claude Code docs (code.claude.com, June 2026). Each mechanic in the skills was then judged against verified harness reality — never from memory.

The single best piece of news came first: neither skill, nor any persona, names a Claude model anywhere. There are zero references to Opus, Sonnet, Haiku, or Fable, no token-limit assumptions, and no model-version behavior baked in. The skills speak only in terms of harness tools — Agent, AskUserQuestion, Explore, shell git — and all of those tools still exist under Fable 5 with compatible signatures. The orchestration logic itself (gates, iteration caps, halt verdicts, JSON-canonical state, idempotent HTML wikis) is pure process design and is entirely model-independent. Fable 5 being a stronger instruction-follower, if anything, makes the persona contracts more reliable, not less. The skills' separation-of-duties design — Coder forbidden from test files, Reviewer forbidden from editing anything, QA re-running tests independently — anticipates exactly the failure modes the new harness's own multi-agent patterns (adversarial verification, judge panels) are built around. The design has aged well. What has aged is the plumbing: the harness grew native capabilities that the skills predate, and one capability it quietly took away.

The design has aged well. What has aged is the plumbing — and one pipe the harness quietly capped: subagents can no longer ask the user anything.

The Cracked Beam

Subagents can no longer talk to your user

The one genuine break is precise and well-bounded. The current harness documents that AskUserQuestion "depends on the main conversation's UI… and is not available to subagents, even when listed in the tools field." Three places in your persona contracts instruct a spawned subagent to do exactly that.

What actually happens today

When an interactive (non-autonomous) /stx-feature wave spawns the Analyst, the persona tells it to "Interview the user (via AskUserQuestion, grouped 2–4 questions per call)" — but the tool is unavailable in that context. In practice the subagent either silently answers its own questions with assumptions (degrading Gate 1's value — the user approves requirements they were never asked about) or stalls. The same applies to the Architect's gap interview and to QA's Vitest-scaffolding approval. The --autonomous path explicitly suppresses these interviews, which is why autonomous runs have been behaving exactly as designed.

  • stx-analyst.md:29 — requirement interview must move to the orchestrator (main loop), with answers passed into the spawn prompt.
  • stx-architect.md:30 — gap interview, same relocation.
  • stx-qa.md:37 — scaffolding approval should become a "return an open question to the orchestrator and pause" contract.
  • All three gates (Gate 1/2/3) and the /stx-fix acceptance gate already run in the main loop — these were always correct and need no change.

The Proposal Drawer

Six tentative changes — for study, not yet applied

Each card below is a concrete, reviewable change specification. None of these have been made. Every card notes its ripple effects under the repo's doc-sync rule: any SKILL.md semantic change requires the matching catalog.json version bump and an npm run build regeneration in the same commit.

Change 1 · Priority P1 — fixes the broken mechanic

Relocate all user interviews to the orchestrator

Files: .claude/skills/stx-feature/SKILL.md (Steps 2–4), .claude/agents/stx-analyst.md, stx-architect.md, stx-qa.md

Beforestx-analyst.md:29 — "Interview the user (via AskUserQuestion, grouped 2–4 questions per call) on: problem, actor, acceptance criteria…"
AfterOrchestrator (SKILL.md Step 2): "BEFORE spawning the Analyst, interview the user via AskUserQuestion (2–4 grouped questions: problem, actor, acceptance criteria, blast radius, out-of-scope). Append the transcript to the Analyst's spawn prompt."
Persona: "You CANNOT reach the user (subagents have no AskUserQuestion). Work from the interview transcript in your prompt. If a blocking ambiguity remains, STOP and return a structured open_questions[] block — the orchestrator will ask and re-invoke you."
WhyHarness fact: AskUserQuestion is unavailable to subagents (sub-agents.md, "Available tools"). Restores the intended human-in-the-loop quality of Gates 1–3.
Impact / Effort / RiskHigh impact (repairs interactive mode) / Medium effort (4 files, an ask-and-respawn loop) / Low risk — autonomous path unchanged.
Ripplestx-feature → 1.5.0 (minor); stx-analyst → 1.1.0, stx-architect → 1.1.0, stx-qa → 1.2.0; catalog.json + npm run build.
Change 2 · Priority P2

Spawn personas by native agent type on Claude Code; keep paste-verbatim as the Cursor fallback

Files: both SKILL.mds (every spawn block); optionally persona frontmatter (description already present)

Beforestx-feature/SKILL.md:195 — "Spawn: Agent with subagent_type: general-purpose … paste the contents of .claude/agents/stx-analyst.md into the agent's prompt verbatim"
After"Spawn: Agent with subagent_type: stx-analyst (the persona file is its system prompt — do NOT paste it). Fallback (harness without registered stx agents, e.g. Cursor): subagent_type: general-purpose + paste verbatim."
WhyAll 10 personas in .claude/agents/ are already auto-registered as agent types in current Claude Code; double-loading the persona (system prompt + pasted copy) wastes tokens and risks divergence.
Impact / Effort / RiskMedium impact (cleaner, cheaper spawns) / Low effort / Medium risk: must verify the Cursor install-time transform still produces a working fallback — the dual-path wording carries that.
Ripplestx-feature → minor bump, stx-fix → minor bump; catalogs + build.
Change 3 · Priority P2

Hard-enforce the Reviewer's read-only contract via frontmatter

Change 4 · Priority P3

Adopt native worktree entry in Step 0.5 / Step 1.5

Files: both SKILL.mds (worktree steps)

Beforegit worktree add .claude/worktrees/<name> -b bugfix/<name> … cd "$WT" … git rev-parse --abbrev-ref HEAD (verify ≠ main)
AfterHybrid: keep git worktree add -b feat/wave-<slug> (preserves your branch naming — native creation would name it worktree-<name>), then EnterWorktree with path: to switch the session in; ExitWorktree at close-out. Keep the branch-≠-main verification.
WhyNative tools switch the session cwd atomically and integrate with the harness's worktree lifecycle; the bare cd approach works but can trip permission prompts in compound commands.
Impact / Effort / RiskLow-medium impact (robustness) / Low effort / Low risk — the hybrid keeps feat/wave-* and bugfix/* naming and the Cursor caveat unchanged.
RippleBoth skills → patch/minor bump; catalogs + build.
Change 5 · Priority P4 — experimental

Resume QA across iterations with SendMessage instead of re-spawning

Files: stx-feature SKILL.md Step 6; stx-fix SKILL.md loop section

BeforeEvery iteration spawns a fresh QA agent that must re-read the test file, state JSON, and prior context from disk.
After"If SendMessage is available in the session, retain the QA agent's ID from its first spawn and resume it per iteration (context intact). Otherwise fall back to fresh spawns (current behavior)."
WhySubagent resume now exists (docs: "Resumed subagents retain their full conversation history") — saves tokens and keeps QA's memory of prior Dev attempts, sharpening repeat-offense detection.
Impact / Effort / RiskMedium impact / Low effort / Medium risk: docs gate it behind CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 (though it worked un-flagged in this session) — hence the capability-check wording, not a hard dependency.
RippleBoth skills → minor bump; catalogs + build.
Change 6 · Priority P5 — evaluate, don't rush

Evaluate the Workflow tool as the engine for the Step 5–6 Dev wave

Files: stx-feature SKILL.md Steps 5–6 (a redesign, not an edit)

TodayThe orchestrator hand-manages eligibility, ≤3-way concurrency, the Dev→Reviewer→QA chain, and parses YAML hand-backs by convention.
CandidateA Workflow script: pipeline(eligibleTasks, dev, reviewer, qa) with schema-validated agent() outputs replacing YAML parsing, phase() progress, and deterministic cap counting in plain JS. Gates and interviews stay in the main loop.

The Keep Pile

What should stay exactly as it is

Verified sound under Fable 5
  • Model-agnostic persona contracts — no model names anywhere; nothing to migrate for Fable 5 itself.
  • --autonomous governance — matches the new harness's autonomous-operation doctrine precisely (no mid-task questions, never commit/push unattended, halt verdicts still trip).
  • Separation of duties (QA-only test edits, read-only Reviewer, smallest-change Coder) — the same adversarial-verification philosophy the new harness promotes natively.
  • JSON-canonical state with rendered HTML and idempotent wikis — robust, harness-independent, and resume-friendly.
  • Iteration caps, suspicious-changes ceiling, and halt-the-loop offenses — pure process logic, fully portable.
  • The catalog.json / SKILL.md / generated-docs pipeline — the harness ignoring version frontmatter is harmless; your build owns it.

The Bottom Line

So — are the skills still relevant?

Yes — decisively. Twelve of fifteen audited mechanics work under Fable 5 as written, and the three that don't share one root cause with one clean fix: interviews belong in the orchestrator, because subagents can no longer reach your user. Apply Change 1 and interactive /stx-feature waves are fully restored; Changes 2–4 are cheap hardening; Changes 5–6 are genuine opportunities the new harness opened up, worth a deliberate look rather than a reflex.
